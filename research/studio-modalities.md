# 健身 / 體適能 / 運動工作室 — 項目類型全景與相容性分析

> 專案：Yolian（有練）
> 目的：窮舉「體能 / 體適能 / 健身 / 健美 / 運動」工作室的所有營運項目類型，分析其異同，並判定**哪些項目性質完全不同、必須排除在 Yolian 訓練引擎之外**。
> 核心判準：Yolian 的引擎是「**可量化、可漸進、個人化編排**的訓練（組×次×負荷 + Program→Cycle→Day→Block）＋ 可測量的體組成/肌力成效」。本文用這把尺去量每一種項目。
> 建立日期：2026-06-25

---

## 0. 為什麼做這份研究（產品問題）

工作室千百種，但 Yolian 不可能、也不該服務全部。既有的 6 個 UI 原型（Pulse/Forge/Velocity/Atelier/Mono/Vital）解決的是「**長相**」問題；本文解決的是更底層的「**引擎吃不吃得下**」問題——這兩件事不一樣（見 §6 的關鍵提醒）。

要回答的就一句：**哪些項目能套進「個人化編排 + 漸進負荷 + 可測成長」這套引擎？哪些性質完全不同、必須排除？**

---

## 1. 全景清單（盡量窮舉）

依「**運作性質**」分成 7 大家族（非依商業包裝）。每項附台灣慣用稱呼。

### A. 肌力 / 阻力訓練家族
自由重量重訓（槓鈴/啞鈴）、器械式重訓（機械/史密斯）、健美（增肌）、健力（深蹲臥推硬舉）、奧林匹克舉重（抓舉/挺舉）、大力士 Strongman（atlas stone/yoke/farmer walk/log press）、CrossFit（混合功能競技）、壺鈴、TRX 懸吊、功能性訓練、徒手／街頭健身（calisthenics）、阻力帶訓練。

### B. 體能 / 代謝 / 間歇家族
飛輪（室內單車）、Hyrox（跑步＋功能站點混合賽制）、HIIT 高強度間歇、循環訓練（circuit）、戰繩／跳箱／增強式（plyo）、划船機工作室（rowing）、風扇車／SkiErg 體能、跑步／跑團、拳擊有氧／有氧舞動（boxfit/aerobics）、Tabata、EMS 電肌肉刺激訓練。

### C. 格鬥 / 武術家族
拳擊、泰拳、MMA（綜合格鬥）、巴西柔術 BJJ、柔道、跆拳道、空手道、散打、踢拳（kickboxing）、摔角／角力、擊劍／劍道。

### D. 身心 / 柔軟 / 低衝擊家族
瑜珈（Hatha/Vinyasa/Ashtanga/Yin/熱瑜珈）、墊上皮拉提斯（mat）、**器械皮拉提斯（reformer/cadillac/chair/barrel）**、伸展／活動度／筋膜放鬆（mobility）、太極、氣功、芭蕾健身（Barre）、冥想／呼吸。

### E. 空中 / 技巧 / 舞蹈家族
空中環／空環（aerial hoop/lyra）、空中綢（silks）、空中瑜珈、鋼管舞／鋼管健身、舞蹈健身（Zumba/有氧舞蹈/街舞）、競技體操／體操、啦啦隊。

### F. 恢復 / 被動 / 健康服務家族
運動按摩／筋膜放鬆、輔助伸展工作室（assisted stretch，如 StretchLab）、三溫暖／桑拿／冷療／冰浴、漂浮艙、物理治療／運動傷害防護、整復／徒手治療。

### G. 場地 / 競技運動家族
攀岩／抱石、游泳／水中有氧、球拍類（網／羽／壁／桌球）、高爾夫模擬、球類（籃／排／足）、滑冰／直排輪。

### ＋ 跨切面：特殊族群（以「對象」分，不是項目）
銀髮族功能性、孕產／產後、兒童體適能、運動員專項體能（S&C）、慢性病健康促進（心肺／代謝復健）。這些是 A/B 家族的「對象變體」，不是獨立引擎需求。

## 2. 分類軸（用什麼維度判斷異同）

判斷「同不同質、排不排除」的五把尺：

| 軸 | 選項 | 為何關鍵 |
|----|------|---------|
| **① 漸進模型** | 負荷／量化漸進 ・ 技術／段位 ・ 柔軟度／體位深度 ・ 成績／耐力 ・ 無（維持/療癒） | Yolian 引擎只懂「**負荷/量化漸進**」 |
| **② 交付模型** | 1對1 編排 ・ 小班半私人編排 ・ 固定團課（套課表） ・ 自助／開放 ・ 預約式服務 | 決定要不要「個人化課表」這個核心物件 |
| **③ 量化顆粒度** | 組×次×負荷 ・ 時間/回合/站點 ・ 流程/編舞 ・ 主觀 | 決定 WorkoutLog 記得下記不下 |
| **④ 空間/器材預約** | 開放地板 ・ 固定工位（reformer/單車/划船/吊掛架） ・ 墊上 ・ 專業場地 | 影響 Booking 模型，不影響引擎核心 |
| **⑤ 成效衡量** | 體組成＋肌力 ・ 成績/時間 ・ 技術段位 ・ 主觀身心 | 決定「學員看得見成長」成不成立（留存王牌） |

## 4. 相同 vs 相異：斷層線在哪

把矩陣收斂，會看到一條**核心斷層線**：

> **這個項目的「進步」靠不靠『可量化的負荷/量』來推動，而且教練是不是在『為個人持續編排』？**

- **YES（同質群）**：肌力家族整片高度同構——換的只是動作與器材，骨架都是「組×次×負荷 → 漸進 → 體組成/肌力證據」。這正是 §5 既有資料模型（Program→Cycle→Day→Block→Exercise + WorkoutLog + BodyComposition）的原生形狀。
- **HALF（部分同質）**：體能/代謝/器械皮拉提斯——**可量化但量綱不同**（彈簧檔位、功率瓦特、時間、距離、回合），或**交付是固定團課而非個人課表**。骨架能用，但「負荷」欄位要變體。
- **NO（異質群）**：瑜珈/舞蹈/太極——進步靠柔軟度、編舞、體位深度，**不靠負荷、也不該被量化成組次**。硬塞進引擎只會讓教練覺得「這軟體不懂我」。
- **完全不同（異種）**：格鬥技術段位、藝術表演、純恢復服務、醫療復健、場地租借——連「教練持續為個人編排訓練 → 學員可測成長」這層**關係本身**都不成立（是一次性服務、是場地自助、是臨床醫療、或是版權固定課）。

## 5. 相容性分級（給產品決策）

| 級別 | 定義 | 項目 | Yolian 對策 |
|------|------|------|------------|
| **T0 核心命中** | 引擎原生支援，零改造 | 肌力家族全體＋CrossFit | **MVP 主攻**。對應 Forge/Velocity/Pulse/Mono 原型 |
| **T1 變體相容** | 需小改造（負荷量綱 or 團課課表） | 器械皮拉提斯、Hyrox、划船、飛輪、HIIT/循環、EMS、拳擊體能 | **MVP 後段～Phase 1.5**。靠 §6 的 `loadType` 一次吃下 |
| **T2 僅外圍層** | 訓練引擎不適用；但排課/會籍/簽到/消課/訊息/品牌頁可服務 | 瑜珈、墊上皮拉提斯、Barre、舞蹈健身、太極 | **非 MVP 主攻**。可當「課程工作室輕量版」，賣 Booking+CRM 不賣引擎 |
| **T3 明確排除** | 性質完全不同，連外圍層的存在理由都不成立 | 見 §6 | **不做** |

## 6. 必須排除的項目（本研究的 Focus）＋ 為什麼

**一句話判準：沒有「教練持續『個人化編排』訓練 ＋ 學員『可測量成長』」這層關係的，排除。**

| 排除項目 | 為什麼性質完全不同 |
|---------|------------------|
| **純恢復 / 被動服務**（按摩、三溫暖、冷療、冰浴、漂浮、輔助伸展 spa 型） | 是**一次性服務預約**，沒有課表、沒有漸進、沒有「成長軌跡」。是 booking 工具的活，不是 Yolian 的活 |
| **醫療物理治療 / 復健**（物理治療所） | 受**醫療法規**管，用的是 SOAP 病歷與臨床指標，不是訓練課表。誤入會踩法遵紅線 |
| **場地租借型競技**（攀岩館、泳池、球場、高爾夫模擬） | 核心是**場地＋自助**，不是「教練為個人編排」。漸進靠路線級數/比分，引擎接不上 |
| **格鬥「技術 / 比賽」養成**（BJJ 腰帶、選手培訓、純技術班） | 漸進是**技術段位＋對練**，不是負荷。成長衡量是腰帶/勝負，不是體組成（這塊更接近 Zen Planner 的腰帶系統，非 Yolian） |
| **純藝術 / 表演導向**（鋼管表演、競技體操、街舞編舞團、空中綢表演） | 漸進是**藝術完成度與編舞**，不是體能負荷 |
| **版權團體操課**（Les Mills / Zumba 授權課） | 是**版權固定編舞**，全班照跳，沒有個人化編排空間 |

### 邊界判斷（別一刀切，這幾個要分兩半看）
- **拳擊 / 泰拳**：拆兩種——「**體能取向**（拳擊有氧、體能對打）」是 T1，引擎服務這半；「**技術/比賽培訓**」是 T3。同一間館兩者都有時，技術那半當純排課即可。
- **皮拉提斯**：別被「UI 有 Atelier 皮膚」誤導——「**器械皮拉提斯**」是 T1（彈簧阻力可量化＋1對1編排），「**瑜珈/墊上**」是 T2。**同視覺、不同引擎相容度**。
- **復健**：純醫療（物理治療所）排除；但「**術後/傷後功能性回歸訓練**」由合格教練做、有漸進負荷 → 可由 T0/T1 引擎＋Vital 原型服務。線畫在「有沒有醫療診斷行為」。

## 7. 對 Yolian 的結論與建議

1. **MVP 主攻 T0＋T1**：肌力 / 體能 / 功能 / CrossFit / 器械皮拉提斯 / Hyrox。這與既有訓練引擎（§5）、品牌原型 Forge/Velocity/Pulse/Mono **完全吻合**，零架構衝突。
2. **T2 留作「輕量版」變現路線（非 MVP）**：瑜珈/舞蹈/團課工作室賣 Booking＋會籍＋消課＋品牌頁，**刻意不賣訓練引擎**——承既有「§1.3 不做什麼」的紀律。
3. **T3 明確不做**：恢復服務、醫療復健、場地競技、格鬥技術段位、藝術表演、版權操課。寫進 §1.3 的排除清單。
4. **資料模型啟示（值得納入 §5）**：既有 `Exercise.category`（肌力/伸展/有氧）**不足以承載 T1 的負荷多樣性**。建議在 Block/動作層引入 **`loadType` 負荷類型**：`重量kg / 彈簧檔位 / 自體重 / 時間 / 距離 / 回合 / 功率W / RPE`。一個欄位，讓同一套引擎一次吃下 T0＋T1，不必為每種項目寫死邏輯。
5. **提醒——別把「UI 原型」當「引擎相容度」**：6 個視覺原型是給「長相」的；T0–T3 是給「引擎」的。Atelier（瑜珈/皮拉提斯同皮膚）底下，器械皮拉提斯與瑜珈的引擎相容度天差地遠。產品決策看 T 分級，不看皮膚。

## 8. 後續：引擎一般化後 T3 的再分類（連動 product-architecture §5.4）

> 本研究的 T 分級前提是「**現行 load-based 引擎（組×次×負荷）零改造**」。後續產品決策（架構 §5.4 多專項擴充）把引擎**一般化**為 `discipline 包 + TrainingItem.attrs`，於是 §6 的部分 T3 要**拆「教練課 vs 場地/服務」兩半**重新看：

| §6 原 T3 項目 | 引擎一般化後 | 說明 |
|--------------|------------|------|
| 場地競技（攀岩/球拍類/高球…） | **教練課 → 個人技術型專項包**（Phase 2+）；**場地租借/自助 → 仍排除** | 線畫在「教練是否為個人持續編排」。攀岩**教練課**納入，攀岩**館場租**不做 |
| 格鬥「技術/比賽」 | **1對1/小班技術教練課 → 可做專項包**；段位/對練自有 attrs | 承 §6 邊界：體能那半本就 T1，技術那半改由專項包承載而非排除 |
| 純恢復服務 / 醫療復健 / 版權固定操課 / 團隊球類 | **維持永久排除** | 無「教練為個人編排 + 可測成長」關係；團隊球類另見 §5.4 明文排除 |

→ 即：T3 不是鐵板，**「個人技術型教練課」會隨 §5.4 的 know-how 包逐步從排除轉為納入**；真正永久排除的是「場地自助 / 醫療 / 版權操課 / 純恢復 / 團隊球類」。§7.4 的 `loadType` 是 TrainingItem.`attrs` 的一個特例。
