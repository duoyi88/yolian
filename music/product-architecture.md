# Yolian Music 產品架構與 MVP 功能地圖 v1

> 專案：**Yolian Music（有練 · 音樂版）** — 面向音樂老師與小型音樂教室的對話式營運平台
> 本文是 Yolian Music 的**完全獨立系統說明**：定位 → 用戶（含家長層）→ 資訊架構 → 產品四面 → 音樂原生引擎 → Agent 能力 → MVP 範圍 → 技術架構 → LINE 整合 → 商業模式 → 與健身版的差異。
> 適配理由與「值不值得做」的判斷見同目錄 `assessment.md`。
> 日期：2026-06-25 · 狀態：v1（系統說明；獨立部署於健身版網頁之外）

---

## 0. 一句話定位

> **Yolian Music = 一個「系統（UI）為主體」的音樂教學營運平台，外加一個 AI 副駕窗口 —— 把「老師的行政效率」「家長看得見孩子的進步」「每週課之間的家庭練習閉環」縫進同一個產品。**
>
> 定位校準：**系統能直接點擊完成所有事**；AI 副駕（Yo）是疊在系統之上的窗口，只在「值得」時介入（老師課後口述、家長隨手記、跨模組、零碎隨手）。**簡單的事用 Dashboard 解決就好，不必丟給 LLM 浪費 token。**

**與健身版同源、不同臉的三個錨點：**
1. **主戰場是「課與課之間」** — 音樂 90% 的進步發生在家庭練習；本產品的核心閉環就是把這段接住。
2. **學員端的真正使用者是家長** — 學生多為兒童，無法自行操作；家長是收提醒、看進度、付錢、盯練習的人。
3. **進步靠曲目精熟與檢定級數**，不是負荷量化 — 訓練引擎是音樂原生的，不沿用健身。

## 1. 策略與切入點

### 1.1 灘頭堡（Beachhead）
**台灣的個人音樂老師 + 小型音樂教室/琴行（1–10 名老師），先主打鋼琴。** 理由：
- 數位化程度**比健身更低**：多數靠 LINE 群 + 紙本聯絡簿 + 老師記憶；在地工具幾乎空白。
- 家長是高焦慮、高付費意願的消費者，對「看得到進度與成果」極敏感。
- **鋼琴市場最大、最標準化**（教本/檢定體系成熟）→ 單一樂器先跑通閉環，再橫向擴樂器。
- 在地（繁中、台灣檢定生態、LINE）是國外音樂教學 SaaS（My Music Staff/Opus1）打不到的弱點。

### 1.2 三層價值主張
1. **老師**：用講的就完成行政與課堂紀錄、課後一句話指派本週作業，少開 Excel／LINE／紙本聯絡簿。
2. **家長**：被 AI 用真實數據與**錄音/影片對比**說出「孩子的進步故事」，知道錢花得值、知道這週孩子練了沒。
3. **AI 副駕 Yo**：不是功能點、也不是唯一入口，而是**疊在系統之上的加值窗口**——老師課後口述、家長隨手打卡時最省事；簡單操作仍走 Dashboard（省 token、更快）。

### 1.3 不做什麼（MVP 階段的紀律）
不做大型連鎖/才藝集團的多分店白標、不自建 C 端找老師的流量市集、不做樂譜銷售商城、不冒用官方檢定認證（只做備考流程追蹤）、MVP 不做線上金流（老師自行對帳）。

## 2. 目標用戶（Personas）★ 含家長層

| Persona | 是誰 | 最痛的事 | Yolian Music 給的解法 |
|---------|------|---------|--------------|
| **個人老師 Teacher Solo** | 自由音樂老師，20–40 名學生，無行政支援 | 排課/補課/收費靠 LINE+腦袋；課後要打字寫聯絡簿、追誰沒練 | 一句話排課/寫課堂紀錄/指派作業；練況自動匯整 |
| **教室主理人 Studio Owner** | 1–10 名老師的琴行/音樂教室 | 多老師排課衝堂、教室借用衝突、堂數到期沒人追、業績難算 | 多老師排課+衝堂偵測、合約到期提醒、經營儀表板 |
| **家長 Guardian** ★ | 琴童的爸媽（學員端真正使用者） | 不知道孩子有沒有進步、上課上了什麼、回家要練什麼、錢花得值不值 | 課後摘要+本週作業推到 LINE、練習打卡、錄音前後對比、檢定成果 |
| **學生 Student** | 5–15 歲為主（也有成人/青少年自學） | 不想練、不知道練到哪、缺成就感 | 遊戲化打卡/連續天數/貼紙、聽自己進步的錄音、看到曲目過關 |

> 主決策者/付費者 = 老師與主理人；**家長/學生端免費**（降低獲客摩擦）。
> **代理關係可選**：兒童 → 家長代管帳號（1 家長 ─ N 子女）；成人/自學青少年 → 本人即使用者，無家長層。

## 3. 設計原則（決定架構的根本）

1. **Agent 與 UI 共用同一「動作層」**（最重要的架構決策）
   平台所有操作都定義成一組有型別的 **Action（命令）+ Query（查詢）**。程式化前端的每個按鈕，和 Yo 的每句話，呼叫同一套 Action。→ 點擊與對話永遠一致；新功能只要新增一個 Action，UI 與 Agent 同時獲得。
2. **Context-aware 副駕（經營+教學副駕，而非生成器）**
   Yo 下決策前能讀到該學生完整脈絡：曲目進度 + 本週練況 + 剩餘堂數 + 檢定倒數 + 家長溝通紀錄。把「生成式 AI」升級成「教學經營副駕」。
3. **寫入必經確認 + 全程留痕**
   每個「寫」動作先回顯「我要做 X，確認嗎？」，執行後寫入 audit log。可回溯、可撤銷。
4. **系統（Dashboard）為主體，Agent 為加值、選擇性使用（省 token）**
   判準：簡單／單一模組／批次／精細 → 用 Dashboard；口語、語音、跨模組、零碎隨手 → 才用 Yo。不把容易點擊解決的事丟給 LLM。
5. **行動優先、跨平台**：老師 Web 後台 + 老師行動端 + **家長端跑在 LINE LIFF（零安裝）**。
6. **讓習慣便宜**：每個高頻動作壓到「10 秒內、手機上、一兩個點擊或一句話」。對家長/小孩尤其要零摩擦——**練習打卡一鍵、錄音一鍵**。
7. **輸入框必須支援語音輸入（STT）**：老師帶課完雙手忙、用講的記課堂紀錄與指派作業最自然；家長也可語音記練習。
8. **雙迴路激勵**（音樂特有）：對**小孩**做遊戲化（連續天數/徽章/曲目過關動畫）養成練習習慣；對**家長**做價值可視化（進步證據/成果）驅動續約。兩者都是留存設計。

## 4. 產品四面（Four Surfaces）★ 比健身多一面「家長端」

```
┌──────────────────────────────────────────────────────────────┐
│                      Yolian Music Platform                       │
│                                                                 │
│   面 2：Agent 窗口 Yo（加值層，非必經、可省則省）                 │
│   ┌────────────────────────────────────────────────────┐      │
│   │ 老師：課後語音「今天上了…，回家練…」→ 寫紀錄+指派作業  │      │
│   │ 家長：語音/一句話「今天練了 20 分鐘」→ 寫練習紀錄      │      │
│   └────────────────────────────────────────────────────┘      │
│                      ▼ （疊在系統之上）                          │
│   面 1：程式化前端（主體 — 老師多數操作在這直接完成）             │
│   儀表板 / 行事曆 / 學生 / 合約堂數 / 曲目計畫 / 課堂紀錄 / 報表  │
│                      │                                          │
│           ┌──────────────────────────┐                         │
│           │   共用 Action / Query 層   │ ← 設計原則 #1           │
│           └──────────────────────────┘                         │
│                      │                                          │
│               核心資料模型 (§5)                                 │
│                      │                                          │
│   面 3：家長端（LINE LIFF）            面 4：學生端（遊戲化練習）  │
│   課後摘要/本週作業/練習打卡/          打卡/連續天數/徽章/        │
│   錄音對比/進度/到期續約               聽自己的錄音/曲目過關       │
└──────────────────────────────────────────────────────────────┘
```

- **面 1 程式化前端（主體）**：老師/主理人的 Web + 行動後台。儀表板、行事曆排課（含固定週課+補課）、學生清單、合約堂數、**曲目計畫編排**、**課堂紀錄**、報表。多數操作在此直接完成。
- **面 2 Agent 窗口 Yo（加值層）**：差異化王牌但疊在系統之上。老師「課後一句話/一段語音寫課堂紀錄 + 指派本週作業」；家長「一句話記練習」。輸入框支援語音。簡單操作不必走它。
- **面 3 家長端（LINE LIFF）**：**本產品學員端的主介面**。課後摘要、本週作業、練習打卡、錄音前後對比、孩子進度、堂數/檢定倒數、到期續約。零安裝、自動帶家長 LINE 身分。
- **面 4 學生端（遊戲化練習）**：給能自己操作的孩子/成人——練習打卡、連續天數、徽章、聽自己的錄音、曲目過關。兒童版多由家長手機代管（面 3 內的「孩子模式」），青少年/成人可獨立。

> 面 3 與面 4 在兒童情境常合一於家長手機（家長端內切「孩子模式」）；在成人/自學情境，面 4 獨立、無面 3。

## 5. 資訊架構與核心資料模型

### 5.1 核心實體（Entities）

| 實體 | 關鍵欄位 | 關係 |
|------|---------|------|
| **Studio** 教室/琴行/工作室 | 名稱、營業資訊、品牌頁設定、教室（房間）清單 | 1 Studio ─ N Teacher |
| **Teacher** 老師 | 姓名、角色權限、抽成設定、個人頁、**可教樂器(可多個)** | N Teacher ─ N Student |
| **Guardian** 家長 ★新增 | 姓名、LINE 身分、聯絡、**代管的子女(可多個)** | 1 Guardian ─ N Student（代理關係，可選） |
| **Student** 學生 | 檔案、年齡、**所屬家長(可空=成人自學)**、在學樂器(可多個)、程度/級數、來源、狀態 | 由 Guardian 代管或自管；1 ─ N Contract/Booking/Log |
| **Instrument** 樂器/專項 | 名稱(鋼琴/小提琴/吉他/聲樂…)、形態(個人/小班)、是否官方分級包、量測指標集 | 標籤：掛 Studio(啟用)/Teacher(能力)/Student(在學)/Plan/Booking/Item |
| **Lead** 線索/潛在學生 | 來源、聯絡(家長)、興趣樂器、**試上課狀態**、雙向評估、轉換狀態 | 屬 Studio/Teacher；轉換成 Student（見 §5.6） |
| **Contract** 合約/堂數包 | 方案、總堂數、剩餘堂數、到期日、金額；或月費 | 屬於 Student；驅動消課 |
| **Booking** 排課/預約 | 時間、老師、教室(房間)、樂器、類型(1對1/小班/**試上課**/**補課**)、狀態、簽到 | 連 Student 或 Lead(試上) + Teacher；消 Contract 堂數 |
| **RepertoirePlan** 曲目計畫/學習路徑 ★音樂引擎 | **所屬樂器**、目標(檢定/興趣/比賽)、程度、含多首 PlanItem | 指派給 Student；可存模板複用 |
| **PlanItem / RepertoireItem** 曲目·練習項 ★音樂引擎 | 名稱、**型別**(曲目/音階/琶音/練習曲/視奏/聽寫/樂理)、調性/拍號、難度級、技巧標籤、**目標速度BPM**、教本出處 | 屬於 Plan；被 Assignment/LessonNote 引用 |
| **Assignment** 本週作業/指派 ★核心閉環 | 本週要練哪些 PlanItem、各自目標(段落/速度/次數)、截止(下次上課)、老師備註 | 老師課後指派 → 推家長；連 PracticeLog 回收 |
| **LessonNote** 課堂紀錄 ★音樂引擎 | 今天上了什麼、各曲完成度/評語、待改進、下週方向；可附課堂錄音片段 | 屬於 Student + Booking（付費課堂） |
| **PracticeLog** 家庭練習紀錄 ★主角 | 日期、時長、練了哪些 PlanItem、家長/學生記、(選)練習錄音、心情 | 屬於 Student；對應 Assignment；零摩擦優先 |
| **Recording** 錄音/錄影 ★留存王牌 | 檔案、曲目、日期、類型(練習/課堂/成果)、(選)老師評註 | 屬於 Student + PlanItem；驅動**前後對比** |
| **Exam / Event** 檢定·比賽·發表會 ★音樂特有 | 類型(英皇/Trinity/山葉/比賽/成果發表)、報名期、考試日、要求曲目、結果/級數/名次 | 屬於 Student/Studio；驅動備考倒數與進度 |
| **RepertoireLibrary** 曲目庫/分級大綱 | 分級曲目、教本進度表、音階琶音表；老師自建 or 官方分級包 | 供 Plan 挑選 |
| **Order / Payment** 訂單金流 | 品項、金額、狀態、發票 | 連 Contract（Phase 1.5 線上金流） |
| **Payroll** 業績/薪資 | 底薪、售課抽成、完課獎金 | 由 Teacher + Booking + Order 算（Phase 1.5） |
| **Message** 溝通 | 對象(家長)、內容、自動/手動、已讀 | 連 Student/Guardian |
| **AgentActionLog** 操作日誌 | 意圖、參數、執行者、前後狀態、可撤銷 | 貫穿所有寫入（設計原則 #3） |
| **Automation** 自動化 | 觸發事件 → 動作鏈 | Phase 2 |

### 5.2 關係重點（六條核心鏈）
- **消課邏輯核心**：Booking 完成簽到 → 扣 Contract 剩餘堂數 → 觸發到期/續約提醒 → 餵副駕算流失風險。（同健身）
- **家庭練習閉環核心 ★本產品命門**：LessonNote/Assignment（老師課後口述指派）→ 推家長 LINE → PracticeLog（家庭每天打卡/錄音）→ 老師上課前看到這週練況 → 下週調整。**這條鏈是與純行政工具拉開差距的關鍵。**
- **成長敘事核心 ★留存王牌**：Recording（同曲第 1 個月 vs 第 6 個月）+ Exam 級數/比賽名次 隨時間累積 → 家長端**音檔/影片前後對比** + AI 敘事。
- **曲目進度核心**：RepertoirePlan → PlanItem（曲目/音階/技巧，帶難度級與目標 BPM）→ 完成度推進；可檢查均衡（曲目/音階/視奏/樂理是否都有顧到）。
- **檢定備考核心**：Exam 報名期/考試日 → 倒數 + 要求曲目納入 Plan → 備考進度追蹤 → 結果回填成成長證據。
- **代理關係核心**：Guardian 1:N Student；通知/付費/查看走家長，練習可家長代記。成人自學則無此層。
- 所有寫入都過 Action 層並落 AgentActionLog。

### 5.3 重點功能展開

#### A. 家庭練習閉環（本產品的主角）★
> 健身版裡的配角（課外追蹤），在音樂版是核心。
- **老師端課後指派**：課後一句話/語音「這週練拜爾 56、C 大調音階兩個八度練到 ♩=100、小星星變奏前兩段」→ Yo 解析成結構化 Assignment（綁 PlanItem + 目標）。
- **推送家長**：Assignment 自動成卡片推到家長 LINE（本週要練什麼、各練到什麼程度）。
- **家庭打卡**：家長/孩子每天一鍵打卡（練了/練多久/練哪首），**可選錄一段音**。零摩擦——一鍵、語音、或在家長手機上點。
- **回收與回饋**：老師上課前一眼看到「這週練了 4 天、音階達標、變奏卡在第二段」→ 針對性上課；可對練習錄音給簡短評註。
- **遊戲化（對孩子）**：連續天數、徽章、曲目過關動畫，把「被逼練」轉成「想完成」。
- **MVP**：Assignment 指派（含語音解析）+ 推家長 + 一鍵打卡（時長/曲目）+ 老師端練況回收視圖 + 連續天數。練習錄音可 MVP 末或 1.5。

#### B. 音樂原生訓練引擎（曲目精熟，非負荷漸進）★
> 進步 = 曲目難度爬升 + 技巧精熟 + 速度達標 + 檢定級數。**完全不沿用健身的組×次×負荷引擎。**
- **曲目·練習項 PlanItem** 帶型別（曲目/音階/琶音/練習曲/視奏/聽寫/樂理）、調性、拍號、**難度級**、技巧標籤（圓滑奏/斷奏/換把/踏板…）、**目標速度 BPM**、教本出處。
- **曲目計畫 RepertoirePlan**：一個學生當前的學習路徑（在練哪幾首 + 音階/技巧/樂理的搭配），可檢查均衡。
- **可量化的進步指標（音樂少數能量化處，要善用）**：**節拍器目標速度達標**（練到 ♩=120 過關）、曲目完成度（讀譜→流暢→背譜→表現）、級數爬升。
- **MVP**：PlanItem + RepertoirePlan + 完成度狀態 + 目標 BPM 達標標記 + 曲目庫（老師自建）。分級官方包留 Phase 2。

#### C. 成長證據與敘事（留存王牌）★
> 把健身的「InBody 體脂↓肌肉↑」換成音樂的「**錄音/影片前後對比 + 檢定成果**」。
- **錄音作為一級物件 Recording**：練習錄音、課堂片段、成果影片。
- **前後對比**：同一首曲子不同時間點的音檔並排播放——家長**最有感**的成長證據（「你聽聽他三個月前 vs 現在」）。
- **檢定/比賽/發表會 Exam/Event**：級數通過、比賽名次、成果發表影片，是最硬的客觀里程碑。
- **AI 成長敘事**：把曲目進度 + 錄音里程碑 + 檢定成果寫成一段給家長的故事（「這學期從拜爾彈到了徹爾尼，C 大調音階從 ♩=60 練到 ♩=120，通過英皇二級」）。
- **MVP**：Recording 上傳 + 前後對比播放 + Exam 里程碑記錄 + 規則版學期摘要；AI 敘事留 Phase 2。

#### D. 排課 / 補課 / 教室預約（音樂更敏感）
- **固定週課**：「每週三 16:00」是音樂鐵律 → 支援週期性循環排程，一次排整學期。
- **補課 make-up ★高頻**：請假→補課額度→改期媒合空檔。家長對「補不補得到」極敏感，要做順。
- **教室（房間）預約**：琴行多間琴房 → Booking 綁房間，偵測房間/老師雙重衝突。
- **MVP**：固定週課循環排程 + 衝堂/房間衝突偵測 + 請假補課 + 簽到消課。

#### E. 多樂器架構（Multi-instrument，同健身多專項）
- **instrument 是「標籤」不是帳號類型**：掛 Studio/Teacher/Student/Plan/Booking/PlanItem。一個學生一份檔、一張帳、一條時間軸；可同時學鋼琴+小提琴。
- **通用包兜底**：「老師自建曲目 + 自訂技巧標籤」→ Day 1 覆蓋任何樂器。官方分級包（英皇鋼琴/山葉…）是付費深度升級，由市場拉動。
- **MVP**：零成本架構保留（instrument 標籤 + PlanItem 抽象 + OS/內容解耦），實際先上線鋼琴。

#### F. 檢定備考生態（音樂特有商機）
- 英皇 ABRSM、Trinity、山葉、河合、音樂班甄試 → 報名期/考試日/要求曲目標準化。
- 做成**備考模板**（對應健身的器材感知教案）：一鍵把某級檢定要求曲目帶入學生 Plan + 設好倒數。
- ⚠️ 只做「備考流程與曲目追蹤」，**不冒用官方認證**；名稱走描述性使用。
- **MVP**：檢定/發表會行事曆 + 倒數提醒；備考模板留 Phase 1.5。

### 6.6 Agent 運作機制
- **輸入**：文字或**語音（STT）**；輸入框一律支援語音（老師課後、家長隨手最需要）。
- **省 token 路由**：明確、簡單、單一模組的請求走規則/捷徑或導去 Dashboard，不必每次呼叫 LLM。
- **意圖解析**：LLM 將自然語言 → 結構化意圖 + 參數（哪個學生、哪首曲、目標速度多少）。**指派作業的口述解析是音樂版最關鍵的 Agent 場景。**
- **歧義澄清**：缺參數或多個「小明」→ 反問確認。
- **寫入確認**：回顯「我要指派小明本週：拜爾57＋C大調音階到♩=100，確認？」→ 執行 → 落 AgentActionLog（可撤銷）。
- **脈絡組裝**：執行前載入該 Student 的曲目進度/近期練況/檢定倒數 → 餵 LLM 做 context-aware 判斷。

## 7. MVP 範圍與分期路線圖

### 7.1 MVP（Phase 0）— 完整可用的系統 UI + Agent 加值 + 家庭練習閉環 + 家長看得見成長

**核心命題：把「課後口述指派 → 家長 LINE → 家庭練習打卡/錄音 → 老師上課前看到」這條閉環跑通，證明它不只是又一個排課工具。**

**IN（做）**：
- **家長代理帳號層**：Guardian 1:N Student、通知/查看/付費走家長；成人自學情境免家長層。
- 學生 CRM（檔案/樂器/程度/時間軸）+ **線索/試上課漏斗**（Lead 狀態、公開約試上、試上一次性定價、轉正帶基線；漏斗分析留 1.5）。
- 排課/預約（固定週課循環排程 + 1對1 + 小班 + 試上課 + **補課** + **教室房間衝突偵測** + 多老師協作衝堂偵測 + 簽到）。
- 合約/堂數（建約、消課、到期提醒〔規則版〕）。

- **音樂訓練引擎（MVP 子集）**：RepertoirePlan + PlanItem（型別/難度級/目標 BPM/技巧標籤）+ 曲目庫（老師自建）+ 完成度狀態。

- **課堂紀錄 LessonNote**：老師課後語音/文字寫今天上了什麼、完成度、待改進。

- **Agent（Yo）操作中樞（MVP 子集）**：§6.1 全部寫入意圖 + §6.2 查詢 + 確認/留痕。
- 老師個人品牌頁（選版型自動生成）。
- **多老師 / 主理人角色權限**（主理人看全教室、老師看自己的學生）。
- 基本經營儀表板（本週堂數/學生數/到期數 + 老師績效概覽）。

**OUT（延後）**：線上金流（**MVP 老師自行對帳/手動標記收款**；線上金流→1.5）、AI 成長敘事、副駕主動推播（先規則版）、官方分級曲目包、備考模板、多分店、白標、自動化工作流、視訊課。

## 8. 技術架構建議

### 8.1 核心原則：API-first + 共用 Action 層
- 所有操作 = 後端一組**型別化 Command / Query**（單一事實來源）。
- 程式化前端（按鈕）與 Agent（function calling）都呼叫同一套 → 一致、好維護、好擴充。
- 每個 Command 自帶權限檢查（含家長代理權限）+ 寫 AgentActionLog。
- **與健身版 Yolian 共用同一 Action 層骨架與通用 OS 模組**（CRM/排課/合約/訊息/權限/Agent runtime）；音樂引擎與家長層是本產品專屬的 bounded context。

### 8.2 平台
- **老師後台**：Web（PWA 起步）+ 行動可用。
- **家長端**：**LINE LIFF（零安裝）為主**（台灣家長都在 LINE）；PWA 備援。
- **學生端（遊戲化）**：兒童多由家長手機代管（家長端內「孩子模式」）；成人/青少年可 PWA 獨立。
- **錄音/錄影**：行動端錄製 + 上傳；儲存與播放要顧頻寬與成本（音檔為主、影片選用）。

### 8.3 AI Stack
- **LLM + tool calling**：意圖解析 + 呼叫 Action；繁中能力要好。**「課後口述 → 結構化作業指派」是本產品最關鍵的解析場景**，需早期實測。
- **STT 語音轉文字**：老師課後、家長隨手必備；繁中辨識品質要顧。
- **省 token 設計**：系統 UI 處理多數操作；簡單意圖走規則/快捷；脈絡按需組裝。
- **Phase 2 視覺/音訊模型**：練習錄音的自動評估（音準/節奏/速度偵測）— 高價值但成本與準確率需評估，故延後（音樂版的「拍照辨識」等價物）。
- **護欄**：寫入確認、audit log、可撤銷、權限邊界（家長只能看自己孩子）。

### 8.4 在地整合（台灣）
LINE（通知/家長端/預約入口）、台灣金流與電子發票（Phase 1.5）、繁中 LLM、在地檢定生態（英皇/山葉/Trinity/河合/音樂班）。

## 9. LINE 官方帳號 + LIFF 整合策略（台灣關鍵渠道）

> 台灣 LINE 約 2,100 萬活躍用戶。對 Yolian Music，**家長就在 LINE 上**，LINE 不只是通知管道，而是**家長端零安裝的主要交付載體**。

### 9.1 三個積木
| 積木 | 是什麼 | 對 Yolian Music 的角色 |
|------|--------|--------------|
| **LINE 官方帳號 (OA)** | 教室/老師在 LINE 的門面（圖文選單、群發、聊天） | 教室 LINE 門面 + 家長入口 + 推播 |
| **Messaging API** | 後端 ↔ LINE 的程式介面（webhook/push/Flex/Rich Menu） | 把 LINE 接進 Action 層：推作業/提醒 + Yo 對話 |
| **LIFF** | LINE 內建瀏覽器跑的 web app，零安裝、自動帶身分 | **家長端主介面**（作業/打卡/進度/錄音對比） |

### 9.2 對接四面 + Agent
```
LINE 官方帳號（家長加好友）
   │
   ├── Rich Menu（永久入口）
   │      └─▶ LIFF App = 家長端（面 3）  零安裝、自動家長身分
   │             本週作業 / 練習打卡 / 課後摘要 / 進度 / 錄音對比 / 續約
   │
   ├── 家長傳訊 ──webhook──▶ Yo（面 2）──reply(免費)──▶ 回覆
   │      「這週要練什麼」「小明下週請假」→ 走同一套 Action/Query
   │
   └── push（計費，高價值才用）
          上課提醒(降爽約) / 本週作業卡 / 練習提醒 / 檢定倒數 / 成長敘事 / 到期續約
```

### 9.3 高價值用例
1. **本週作業卡推到家長 LINE**：老師課後口述 → Yo 結構化 → Flex 卡片推家長（音樂版最剛需的 push）。
2. **降低爽約 + 補課**：課前提醒 + 一鍵請假/改期 → 自動進補課媒合。
3. **練習提醒（溫和）**：到了該練的時間給家長/孩子一個輕推（依從性設計，避免變騷擾）。
4. **零安裝家長端**：加好友即用，移除「下載 App」流失點。
5. **成長敘事 + 錄音對比 push**：每學期把進步講成一段話 + 附音檔對比推給家長（留存+轉介王牌）。
6. **轉介獲客**：`shareTargetPicker` 家長把孩子的成果/錄音分享給另一半、長輩、朋友。

### 9.4 成本與限制（務實）
- **計費**：reply（回覆）免費；群發/API push 計費 → **Yo 對話走 reply（免費）、提醒/作業卡才用 push（精省）**。
- **TW 方案**：輕/中/高用量（數字以官網計算機為準），各含免費訊息額度。
- LIFF 限制：需 HTTPS、OpenChat 不支援、外部瀏覽器無法用 `scanCode`。

### 9.5 對 MVP 的建議
- **MVP 就把 LINE 當家長端主要交付**：LINE Login 綁家長身分 + LIFF 家長端（作業/打卡/進度）+ Rich Menu + 上課提醒/本週作業卡/到期 push。CP 值極高、在地剛需。
- 老師端仍以 Web 後台為主，LINE 作老師零碎指令補充入口。
